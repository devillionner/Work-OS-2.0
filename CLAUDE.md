# Work OS 3.0

Особиста робоча панель для керування чатами, лідами й публікаціями з аналітикою — все в одному місці.
Приватний хмарний вебзастосунок (PWA) для ПК і смартфона. Один власник, один оператор.

## Робочий процес
- Завжди відповідай українською. Коміти — коротко, українською.
- Працюємо прямо в `main`. Push у `main` автоматично оновлює staging (Cloudflare Workers Builds), тому перед кожним push обов'язково:
  `npm run lint && npm run typecheck && npm run build`. Падіння будь-якого кроку означає не пушити.
- Нових тестів не писати, тестові набори не запускати. Тести, що перевіряли розмітку чи CSS старого UI, видаляються, а не лагодяться.
- Візуальна перевірка замість тестів: браузерне прев'ю на 390×844 і 1440×900, у «Ночі» з атмосферами «Туман», «Промені», «Глибина», «Аврора», «Ртуть» і «Синя сталь».
- Після кожного завершеного етапу онови `lib/app-meta.ts`: `APP_VERSION`, `APP_RELEASE_DATE`, `APP_CHANGES` (3–5 простих пунктів про реальну користь для оператора). Синхронізуй `"version"` у `package.json`.
- Залежності: дозволені тільки ті, що перелічені в розділі «Стек». Будь-яка інша нова залежність потребує мого прямого дозволу.

## Інфраструктурні запобіжники (не обговорюються)
- Ніколи не виконувати `wrangler deploy`, міграції чи будь-які команди D1 з `--remote`. Production (`work-os-production`) недоторканний.
- Єдина дозволена віддалена команда: `node scripts/d1-insights.mjs` (лише читання статистики staging).
- Бюджет D1: звичайний робочий день до 100 000 прочитаних рядків, у простої 0.
- Жодного опитування D1 за таймером. Зміни надходять live-каналом (Durable Object `workers/owner-channel.js` → `/api/live`, клієнт `lib/live-channel.ts`). Таймер дозволений тільки як фолбек, поки канал недоступний.
- Бекенд заморожений: `lib/`, `db/`, `workers/`, `app/api/`, `migrations/`, `scripts/`. UI використовує наявні API і дані. Новий ендпоінт чи SQL — тільки якщо без нього функція неможлива, з індексом і без сканування всіх записів власника.
- Фронтенд-зміни не потребують перезапуску runner на ПК оператора. Якщо зміна все ж його потребує, скажи про це явно.

## Стек
vinext (App Router, сумісний з Next, на Vite + Cloudflare Workers) · React 19 · Tailwind CSS v4 (CSS-first, `@theme` у `app/globals.css`, без `tailwind.config`) · @base-ui/react (лише як безстильні доступні примітиви) · GSAP + @gsap/react (useGSAP, Flip, Draggable) · lucide-react (stroke 1.5) · recharts (тільки в чанку аналітики) · cmdk (палітра команд) · @fontsource-variable/geist + @fontsource-variable/geist-mono (з кирилицею; якщо кирилиці немає — Onest Variable).
Заборонено: framer-motion, стильові пресети shadcn, CSS-in-JS, глобальні стейт-бібліотеки, react-query, іконкові шрифти.

## Дизайн-система «Frosted Field»
Суть: кінематографічне матове скло поверх атмосферного поля, монохромна типографіка, чорна «рейка» навігації, сигнальні кольори тільки для стану. Тиша замість декору.
- Тема лише одна — «Ніч». Тем «День», «Система», «Металік», «Металік синій» немає, перемикача теми в інтерфейсі немає. Різноманіття дає атмосфера (тло за склом), а не тема. Атрибут `data-theme="night"` на `<html>` стоїть у розмітці, інлайн-скрипт до першого рендеру ставить лише атмосферу й щільність, без мигання.
- Єдине джерело токенів — `:root` / `[data-theme]` у `app/globals.css`. Захардкоджені кольори, радіуси й тіні в компонентах заборонені, тільки токени.
- Радіуси: рамка застосунку 3rem · панель 2rem · картка 1.5rem · внутрішній блок 1rem · контроли й кнопки — pill. Правило концентричності: внутрішній радіус = зовнішній − відступ.
- Шрифт: Geist. Вага ≤ 600, ієрархія будується розміром і прозорістю, а не жирністю. Усі числа — `tabular-nums`. Регістр — як у реченні, без КАПСУ кирилицею.
- Текстура: один глобальний шар SVG-шуму (feTurbulence) на `body::after`, `pointer-events:none`.
- Скло: максимум 2 шари `backdrop-filter` в одному в'юпорті. На елементах списку, що прокручується, blur не ставимо. Фолбек — суцільна поверхня для `prefers-reduced-transparency` і браузерів без `backdrop-filter`.
- Рух: GSAP, анімуємо тільки transform, opacity і filter. Анімації короткі, спокійні й функціональні — тільки перехід між станами і відгук на дію: 120–240 мс для відгуку, ≤ 320 мс для панелей, ease `expo.out` / `power3.out`. Без пружин і overshoot. Жодних ефектів, що реагують на наближення чи рух курсора. Поява блоків розділу — лише при першому відкритті, не при кожному поверненні. Усе загорнуто в `gsap.matchMedia()` з гілкою для `prefers-reduced-motion`.

## Архітектура фронтенду
- `app/globals.css` — токени, база, шум, утиліти скла (≤ 350 рядків).
- `components/ui/` — примітиви системи.
- `components/shell/` — каркас: AppFrame, Rail, Topbar, Dock, PulseRail, Inspector, Sheet, CommandPalette, Atmosphere (+ `atmosphere-light.tsx`: шари «Променів», «Глибини» й «Аврори»), ThemeProvider (лише атмосфера й щільність).
- `components/motion/` — одноразова реєстрація GSAP-плагінів (тільки на клієнті), хуки useReveal, useCountUp, спільні таймлайни.
- `components/views/<розділ>/` — today, platforms, leads, analytics, reports, library, settings. Кожен розділ підвантажується ліниво.
- Деталі сутностей відкриваються в Inspector (праворуч, на ПК) або в Sheet (знизу, на телефоні). Модальні діалоги — тільки для підтверджень.

## Ухвалені рішення
- Blur — окремий клас `.frost` (проп `blur` у `Surface`): лише полотно, Inspector, Sheet і меню. Картки й плитки — `.glass` без blur, інакше бюджет «≤ 2 шари» не тримається.
- Атмосфера й щільність — зовнішній стор у `components/shell/theme-provider.tsx` (`useTheme`, `useSyncExternalStore`), без React-контексту; початковий стан ставить інлайн-скрипт у `<head>`.
- Lint: `oxlint --threads=1 app components db lib scripts tests` — чистий на всьому репозиторії, без жодного `oxlint-disable`.
- Літеральні кольори дозволені лише там, де CSS-змінні неможливі: `themeColor` у `app/layout.tsx`, `app/manifest.ts` і мета-тег `theme-color` у `theme-provider.tsx` (дзеркалять `--field` «Ночі»). Решта — тільки токени з `globals.css`. Бекенд (`app/api`, `/audit-access`) заморожений і поза цим правилом.
- Атмосфери можуть перевизначати лише непрозорість `--glass`, `--glass-strong`, `--glass-inner` (скло на склі: картки на полотні), `--noise-opacity` і тло `--field` (через `[data-atmosphere]`), щоб текст тримав AA над найсвітлішими відблисками. На телефоні поза картками текст лежить прямо на атмосфері, тож металеві атмосфери мають усередині плоску вуаль `--atm-veil`. Фоновий рух металевих атмосфер — лише `transform`/`opacity`, 20–90 с, yoyo, `sine.inOut` (симетричний дрейф без overshoot), на паузі при `document.hidden`, вимкнений при `prefers-reduced-motion`. Контраст перевіряється скриптом: `--ink-2` ≥ 4.5:1, `--ink-3` ≥ 3:1 на склі над найсвітлішою точкою атмосфери після blur полотна; при нестачі піднімається непрозорість скла, а не яскравість тексту.
- «Промені», «Глибина», «Аврора» — синє світло (#1C3AF8…#9CB2FF, без фіолетового) на тлі `#02030A` (`--field` пресета). Розмиті плями й віяло — статичний `filter: blur()`, рухаються лише `transform`/`opacity`: віяло повертається на ±3,5° за 75 с, стовп «дихає» ±12 % за 25 с, ядро «Глибини» ±10 % за 30 с, смуги «Аврори» гойдаються й ковзають у різних фазах. Віяло «Променів» гасне з відстанню від джерела (маска), інакше воно заливає екран. Плівкове зерно — сірий `feTurbulence` (0,95; 3 октави) з `mix-blend-mode: overlay` на `body::after` з `--noise-opacity: 0.2`; воно лежить над склом, бо blur полотна змив би власне зерно атмосфери. Непрозорість скла виміряно за найгіршою точкою (стовп, нитка, ядро) у найгірших фазах руху із запасом на зерно: ПК — `--glass` 0.66 / 0.44 / 0.56 (Промені / Глибина / Аврора), `--glass-inner` (картки на полотні) прозоріше, щоб світло було видно й крізь них (під текстом у картці скла завжди більше, ніж у полотна); телефон — вуаль `--atm-veil` 60 % / 35 % / 60 % і скло карток 0.32, бо текст лежить на вуалі без blur.
- Атмосфера статична (дрейф плям прибрано разом з іншими декоративними анімаціями). Передзавантажується лише код розділів (`requestIdleCallback` і hover/focus на пункті навігації), дані — тільки при відкритті розділу; привиди з'являються через 300 мс (CSS-затримка `.ghost`).
- Стан задач Viber safe-mode не опитується за таймером (live-канал їх не віддає): перечитується на focus/visibility/online і кнопкою.
- Скролбар: Chromium/Safari — `::-webkit-scrollbar` (тонкий округлий повзунок на прозорому треку, виразніший при hover і під час скролу через `data-scrolling` з `useScrollActivity`); Firefox — стандартні `scrollbar-width/color`. У Chromium 121+ задані `scrollbar-*` вимикають webkit-стилі, тому в `@supports selector(::-webkit-scrollbar)` вони скидаються на `auto`.
- Локальне прев'ю: `vinext dev` не стартує (клас Durable Object не експортується в dev). Для візуальної перевірки — `npm run build`, потім `npx wrangler dev --local --port 3000` на локальній D1 із синтетичним власником `owner@example.test`.

## Карта екранів
Функція прототипу 2 → місце в 3.0. Нічого не губиться; рідкісне й технічне живе в «Налаштування → Сервіс».
Позначки: [шелл] каркас · [inspector] праворуч на ПК / Sheet знизу на телефоні · [підтвердження] модальний ConfirmDialog.

**Каркас**
- Навігація (Сьогодні, Платформи, Ліди, Аналітика, Звіти, Бібліотека, Налаштування) → Rail на ПК, Dock + «Ще» на телефоні. Лічильник лідів → тільки в підписі розгорнутої Rail.
- Заголовок розділу, дата → Topbar. Привітання за часом доби → «Сьогодні».
- Глобальні таймери (платформа, 5/10/15 хв, звук, закриття) → Topbar: кнопка-pill з найближчим таймером → скляне меню (Sheet на телефоні).
- Обліковий запис, вихід → меню аватара в Topbar + «Налаштування → Профіль».
- Що змінилося (`AppReleaseDialog`), версія → «Налаштування → Сервіс → Версія» + палітра команд.
- Тест екрана оновлення, автооновлення PWA (банер, екран прогресу, відновлення розділу й скролу) → екран оновлення перестилізовано (`pwa-registration`); тест — «Налаштування → Сервіс».
- Збереження активного розділу (`view-persistence`) → стан розділу в `components/shell` (localStorage), без DOM-хаків.
- Вхід через Google, екран завантаження, ліміт D1 → один екран входу в стилі «Frosted Field».
- Нове: палітра команд (⌘K), PulseRail (телефон).

**Сьогодні** (перший екран відповідає на «що мені зробити зараз»; порядок на ПК: шапка дня, KPI, потім «Що зробити зараз» і розклад поруч; на телефоні: шапка, «Що зробити зараз», KPI 2×2, розклад)
- Робочий день (почати, пауза, продовжити, завершити з підтвердженням незавершених, повернути, скинути з підтвердженням, план дня) → компактна шапка в один рядок (`workday-panel.tsx`): дата й привітання, активний час і стан, одна головна дія за станом дня (пауза / продовжити / повернути; «Завершити» тихо поруч). До старту дня в шапці головної кнопки немає: «Почати день» — перший рядок «Що зробити зараз», тож на екрані вона одна. «План дня: цілі й напрямки» (відкриває `GoalsPanel`, там самі цілі й напрямки), підпис фіксованого плану й «Скинути день» — у меню «⋯».
- Налаштування цілей і напрямків (`TodaySettingsDialog`: денна/місячна ціль, цільова конверсія, напрямки) → [inspector], відкривається з меню «⋯» шапки дня і з «Налаштування → Цілі дня».
- Історія цілей (`GoalHistoryDialog`) → [inspector] з «Налаштування → Цілі дня».
- Цілі дня (публікації, нові чати, відгуки, записи) → компактна KPI-стрічка (`kpi-strip.tsx`): число й ціль («0 / 140») і тонка смужка прогресу, без декоративної напівплитки й великих іконок. Розбивка показника за платформами — в Inspector плитки (`kpi-panel.tsx`) замість окремої таблиці «Платформи сьогодні»; там само кнопка переходу на потрібний розділ.
- «Що зробити зараз» (`now-list.tsx`) замість картки «Фокус»: рядки «число · справа · перехід», зібрані зі знімка «Сьогодні» і розкладу Telegram, що вже завантажені (без нових запитів), за терміновістю: «Почати день» (до старту), пропущені публікації, прострочені ліди й нагадування, найближча публікація, публікації й чати до цілі (після старту), звіт (після 18:00 або коли день завершено; після здачі — «події після звіту»). Прострочені ліди й нагадування (`lead-tasks.tsx`: копіювати, надіслано, відкрити ліда; секції Сьогодні/Завтра/Повторні контакти; до 4 рядків, решта — у «Ліди») — усередині цього блоку; якщо їх немає, один тихий рядок «Прострочених немає». Найтерміновіша дія — світла кнопка, решта контурні.
- Розклад Telegram на сьогодні → вертикальний список слотів поруч із «Що зробити зараз» (`schedule-card.tsx`): час, чат, «Готово» й «В архів», лінія «зараз», найближчий слот підсвічений, список відкривається на «зараз»; порожній розклад — один рядок «Розклад на сьогодні не створено» і «Створити». Повне керування (генерація, налаштування, слоти, архів, відв’язати) → «Платформи → Telegram → Розклад».

**Ліди** (`components/views/leads`, дані з `lib/leads`)
- Топбар: перемикач «Дошка | Список», кнопка порядку за давністю відгуку («Новіші спершу» за замовчуванням / «Старіші спершу», зберігається в `localStorage` пристрою; працює в кожній колонці дошки й у списку, а клік на заголовку «Відгук» у списку — те саме, що кнопка; сортування за іншою колонкою вимикає її, доки не натиснуть знову; ліди без дати завжди в кінці) і пошук; «Новий лід» — в меню «Створити» та в кінці колонки «Відгук». Дошка — колонки за етапами воронки (`FUNNEL_STAGES`), перетягування миші/стилуса змінює етап (оптимістично, з відкатом); на телефоні дошка — стрічка зі scroll-snap, етап змінюється в картці. Список — таблиця з сортуванням.
- Відгуки й записи за день → смуга над дошкою. Фільтри (Активні, Усі відгуки, У куратора, Потрібно уточнити, Прострочені, Архів) — чіпи.
- Inspector ліда (`?lead=…`): шапка (контакти, воронка, наступна дія, факти, перша відповідь, редагування, скасування відгуку, архів) + вкладки Розмова · Нагадування · Заняття · Учні · Історія · Скрипти. Форми редагування — кроки всередині панелі, підтвердження — модальні.
- «Ліди | Учні» як окремий список учнів неможливий без нового ендпоінта: учні лишаються вкладкою «Учні» в Inspector ліда.

**Платформи** (`components/views/platforms`)
- Ліворуч: платформа (Topbar), дії «Додати чати» / «Знайти чати» / «Дублікати», черги з лічильниками (для Telegram — один пункт «Відібрані» з лічильником вибраного списку; коли його вибрано, нижче стовпчиком списки-профілі `selected-list-picker.tsx`: «Відібрані 1 · N», вибраний підсвічений, «+ Новий список» унизу; олівець «Редагувати назву» при наведенні, на телефоні завжди, перейменування прямо в рядку: Enter/галочка підтверджує, Esc/X скасовує, порожню назву не зберігаємо; «⋯ → Видалити список» з підтвердженням, останній список видалити не можна; на телефоні списки — горизонтальна стрічка зі scroll-snap), пошук, фільтр профілів і список чатів; праворуч — зона платформи з вкладками: Огляд (ціль публікацій, приєднані/опубліковані з копіюванням, Telegram-акаунти й перерва, перевірка заявок WhatsApp), Розклад (Telegram), Автопост (WhatsApp), Швидкий режим (Viber). На телефоні — сегмент «Чати | Огляд | …».
- Рядок чату: головна дія черги + меню (профіль, +3 дні, повернути, «Я вийшов», видалити назавжди, копіювати, відкрити, історія, архів, перепризначити акаунт). Скасування протягом 8 с — у Toast. Причина архівації, перепризначення, повернення до приєднання, видалення назавжди — підтвердження.
- Telegram «Для приєднання» — два блоки (`join-sections.tsx`). «Черга приєднання»: чати вибраного акаунта (`to_join` з `telegram_account_id` і `join_candidate_at`, порядок відбору), дії «Приєднано» / «В очікування» / «В архів»; лише «Приєднано» з черги рахується в серії приєднань і автоперерві; копіювання «Посилання» / «Назви + посилання» блоками по 5. «Нові чати»: `to_join` без акаунта, партіями по 5 («Партія N · № a–b»), головна дія «У чергу» (закріплює чат за акаунтом, вибраним у цю мить), «Показати ще (N)». З черги чат не зникає в нікуди: «Прибрати з черги» повертає його в нові, «Повернути в чергу приєднання» (меню чату «Для публікації», з підтвердженням, якщо чат у слоті розкладу — слот звільняється) і відновлення з архіву кладуть чат у чергу. «Топ-N до приєднання» з «Відібрані» додає одразу в чергу вибраного акаунта. Лічильник «Для приєднання» = черга вибраного акаунта + нові чати (з `chat_queue_counts`, без нових лічильників).
- «Відібрані» праворуч (`selected-chats.tsx`, `selected-rows.tsx`, `selected-in-work.tsx`) — робота партіями: липка шапка (назва, «N чатів · нових M · файл від …», «Замінити файл») і «Наступні N з M» з розміром партії 10/25/50 (зберігається) та головною дією «+ Усі N у чергу» (в чергу вибраного акаунта; без «Скасувати», бо наявне API не вміє безпечно прибирати створені чати). Рядки компактні: номер у файлі, назва, посилання, повідомлення й дата (mono), «+ У чергу» і «×» «Пропустити»; після дії рядки гаснуть, решта зсувається Flip, партія добирається. Під партією один згорнутий рядок «Уже в Work OS · N» із розбивкою за статусами; розгортання — компактний список зі статусом і акаунтом (сторінки по 50) і група «Пропущені · N» з «Повернути»; стан згортання зберігається. Пропущені посилання зберігаються в метаданих списку в `user_settings` (`dismissed`, дії `skip`/`unskip`, один запис на дію, без нових читань). Пошук із текстом іде по всьому списку (до 50 + «Показати ще»), порожнє поле повертає партію. Нових не лишилось — «Усі чати цього списку вже в Work OS або пропущені.»; порожній список — одна дія «Завантажити файл» і короткий опис формату. Файл завжди імпортується у вибраний список. Лічильники черг ліворуч видно й у «Відібраних»: для цього один разовий запит `/api/chats?status=to_join&limit=1` (лише коли лічильників акаунта ще немає або прийшла live-подія).
- Inspector/Sheet: профіль і правила, публікація (матеріал, мова, швидкий режим), історія чату, додати чати, автопошук WhatsApp, менеджер дублікатів. CSV і перевірка назв чатів — «Налаштування → Сервіс». Панель executor — «Налаштування → Сервіс» (`executor-card`); в автопошуку лишився лише стан runner.
- Окремої «Історії» платформи в даних немає: історія — по чату.

**Аналітика** (`components/views/analytics`)
- Період (День · Тиждень · Місяць · Рік · Довільно) → Segmented у Topbar, дати «Довільно» — рядок над контентом; «Експорт» (CSV) → контурна pill. Попередній період читається другим легким запитом `/api/analytics?compare=1` (підсумки, тренд і агрегат платформ з тих самих рядків; лише за діями користувача, без таймера), на ньому тримаються дельти KPI, пунктир графіка й порівняння платформ.
- KPI з дельтою й міні-лінією (сигнальний колір лише для значущої зміни), графік recharts у окремому чанку (поточний — суцільна, попередній — пунктир, штрихування 45°; довгі періоди складаються в кошики до 120 точок), інсайти (план/факт, зміна, розрив з ціллю, одна наступна дія, архів), картка «Платформи» одразу після графіка (речення-підсумок з чисел; показник Відгуки · Записи · Проведені · Конверсія; рейтинг смужками з частками й дельтою до порівняльного періоду; у «Конверсії» воронка платформи в один рядок і мітки «Найкраща», «Просідає», «Мала вибірка» — пороги в `platform-compare.ts`; клік на платформу ставить її фільтр у рейтингу чатів і гортає до нього), воронка «Де втрачається результат» з результатом уроків, предмети, рейтинг чатів із фільтрами та смужками, когорти («Що сталося з відгуками») → теплова карта по платформах і чатах-джерелах.
- Показник (`analytics-metric-dialog`) → [inspector] `metric-panel`: що рахуємо, формула, події періоду.
