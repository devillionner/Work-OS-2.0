# Work OS 3.0

Особиста робоча панель для керування чатами, лідами й публікаціями з аналітикою — все в одному місці.
Приватний хмарний вебзастосунок (PWA) для ПК і смартфона. Один власник, один оператор.

## Робочий процес
- Завжди відповідай українською. Коміти — коротко, українською.
- Працюємо прямо в `main`. Push у `main` автоматично оновлює staging (Cloudflare Workers Builds), тому перед кожним push обов'язково:
  `npm run lint && npm run typecheck && npm run build`. Падіння будь-якого кроку означає не пушити.
- Нових тестів не писати, тестові набори не запускати. Тести, що перевіряли розмітку чи CSS старого UI, видаляються, а не лагодяться.
- Візуальна перевірка замість тестів: браузерне прев'ю на 390×844 і 1440×900, у «Ночі» з атмосферами «Туман», «Промені», «Глибина», «Аврора», «Ртуть» і «Синя сталь».
- Після кожного завершеного етапу онови `lib/app-meta.ts`: `APP_VERSION`, `APP_RELEASE_DATE`, `APP_CHANGES` (3–5 простих пунктів про реальну користь для оператора). Синхронізуй `"version"` у `package.json`.
- Залежності: дозволені тільки ті, що перелічені в розділі «Стек». Будь-яка інша нова залежність потребує мого прямого дозволу.

## Інфраструктурні запобіжники (не обговорюються)
- Ніколи не виконувати `wrangler deploy`, міграції чи будь-які команди D1 з `--remote`. Production (`work-os-production`) недоторканний.
- Єдина дозволена віддалена команда: `node scripts/d1-insights.mjs` (лише читання статистики staging).
- Бюджет D1: звичайний робочий день до 100 000 прочитаних рядків, у простої 0.
- Жодного опитування D1 за таймером. Зміни надходять live-каналом (Durable Object `workers/owner-channel.js` → `/api/live`, клієнт `lib/live-channel.ts`). Таймер дозволений тільки як фолбек, поки канал недоступний.
- Бекенд заморожений: `lib/`, `db/`, `workers/`, `app/api/`, `migrations/`, `scripts/`. UI використовує наявні API і дані. Новий ендпоінт чи SQL — тільки якщо без нього функція неможлива, з індексом і без сканування всіх записів власника.
- Фронтенд-зміни не потребують перезапуску runner на ПК оператора. Якщо зміна все ж його потребує, скажи про це явно.

## Стек
vinext (App Router, сумісний з Next, на Vite + Cloudflare Workers) · React 19 · Tailwind CSS v4 (CSS-first, `@theme` у `app/globals.css`, без `tailwind.config`) · @base-ui/react (лише як безстильні доступні примітиви) · GSAP + @gsap/react (useGSAP, Flip, Draggable) · lucide-react (stroke 1.5) · recharts (тільки в чанку аналітики) · cmdk (палітра команд) · @fontsource-variable/geist + @fontsource-variable/geist-mono (з кирилицею; якщо кирилиці немає — Onest Variable).
Заборонено: framer-motion, стильові пресети shadcn, CSS-in-JS, глобальні стейт-бібліотеки, react-query, іконкові шрифти.

## Дизайн-система «Frosted Field»
Суть: кінематографічне матове скло поверх атмосферного поля, монохромна типографіка, чорна «рейка» навігації, сигнальні кольори тільки для стану. Тиша замість декору.
- Тема лише одна — «Ніч». Тем «День», «Система», «Металік», «Металік синій» немає, перемикача теми в інтерфейсі немає. Різноманіття дає атмосфера (тло за склом), а не тема. Атрибут `data-theme="night"` на `<html>` стоїть у розмітці, інлайн-скрипт до першого рендеру ставить лише атмосферу й щільність, без мигання.
- Єдине джерело токенів — `:root` / `[data-theme]` у `app/globals.css`. Захардкоджені кольори, радіуси й тіні в компонентах заборонені, тільки токени.
- Радіуси: рамка застосунку 3rem · панель 2rem · картка 1.5rem · внутрішній блок 1rem · контроли й кнопки — pill. Правило концентричності: внутрішній радіус = зовнішній − відступ.
- Шрифт: Geist. Вага ≤ 600, ієрархія будується розміром і прозорістю, а не жирністю. Усі числа — `tabular-nums`. Регістр — як у реченні, без КАПСУ кирилицею.
- Текстура: один глобальний шар SVG-шуму (feTurbulence) на `body::after`, `pointer-events:none`.
- Скло: максимум 2 шари `backdrop-filter` в одному в'юпорті. На елементах списку, що прокручується, blur не ставимо. Фолбек — суцільна поверхня для `prefers-reduced-transparency` і браузерів без `backdrop-filter`.
- Рух: GSAP, анімуємо тільки transform, opacity і filter. Анімації короткі, спокійні й функціональні — тільки перехід між станами і відгук на дію: 120–240 мс для відгуку, ≤ 320 мс для панелей, ease `expo.out` / `power3.out`. Без пружин і overshoot. Жодних ефектів, що реагують на наближення чи рух курсора. Поява блоків розділу — лише при першому відкритті, не при кожному поверненні. Усе загорнуто в `gsap.matchMedia()` з гілкою для `prefers-reduced-motion`.

## Архітектура фронтенду
- `app/globals.css` — токени, база, шум, утиліти скла (≤ 350 рядків).
- `components/ui/` — примітиви системи.
- `components/shell/` — каркас: AppFrame, Rail, Topbar, Dock, PulseRail, Inspector, Sheet, CommandPalette, Atmosphere (+ `atmosphere-light.tsx`: шари «Променів», «Глибини» й «Аврори»), ThemeProvider (лише атмосфера й щільність).
- `components/motion/` — одноразова реєстрація GSAP-плагінів (тільки на клієнті), хуки useReveal, useCountUp, спільні таймлайни.

## Ухвалені рішення
- Blur — окремий клас `.frost` (проп `blur` у `Surface`): лише полотно, Inspector, Sheet і меню. Картки й плитки — `.glass` без blur, інакше бюджет «≤ 2 шари» не тримається.
- Атмосфера й щільність — зовнішній стор у `components/shell/theme-provider.tsx` (`useTheme`, `useSyncExternalStore`), без React-контексту; початковий стан ставить інлайн-скрипт у `<head>`.
- Lint: `oxlint --threads=1 app components db lib scripts tests` — чистий на всьому репозиторії, без жодного `oxlint-disable`.
- Літеральні кольори дозволені лише там, де CSS-змінні неможливі: `themeColor` у `app/layout.tsx`, `app/manifest.ts` і мета-тег `theme-color` у `theme-provider.tsx` (дзеркалять `--field` «Ночі»). Решта — тільки токени з `globals.css`. Бекенд (`app/api`, `/audit-access`) заморожений і поза цим правилом.
- Атмосфери можуть перевизначати лише непрозорість `--glass`, `--glass-strong`, `--glass-inner` (скло на склі: картки на полотні), `--noise-opacity` і тло `--field` (через `[data-atmosphere]`), щоб текст тримав AA над найсвітлішими відблисками. На телефоні поза картками текст лежить прямо на атмосфері, тож металеві атмосфери мають усередині плоску вуаль `--atm-veil`. Фоновий рух металевих атмосфер — лише `transform`/`opacity`, 20–90 с, yoyo, `sine.inOut` (симетричний дрейф без overshoot), на паузі при `document.hidden`, вимкнений при `prefers-reduced-motion`. Контраст перевіряється скриптом: `--ink-2` ≥ 4.5:1, `--ink-3` ≥ 3:1 на склі над найсвітлішою точкою атмосфери після blur полотна; при нестачі піднімається непрозорість скла, а не яскравість тексту.
- «Промені», «Глибина», «Аврора» — синє світло (#1C3AF8…#9CB2FF, без фіолетового) на тлі `#02030A` (`--field` пресета). Розмиті плями й віяло — статичний `filter: blur()`, рухаються лише `transform`/`opacity`: віяло повертається на ±3,5° за 75 с, стовп «дихає» ±12 % за 25 с, ядро «Глибини» ±10 % за 30 с, смуги «Аврори» гойдаються й ковзають у різних фазах. Віяло «Променів» гасне з відстанню від джерела (маска), інакше воно заливає екран. Плівкове зерно — сірий `feTurbulence` (0,95; 3 октави) з `mix-blend-mode: overlay` на `body::after` з `--noise-opacity: 0.2`; воно лежить над склом, бо blur полотна змив би власне зерно атмосфери. Непрозорість скла виміряно за найгіршою точкою (стовп, нитка, ядро) у найгірших фазах руху із запасом на зерно: ПК — `--glass` 0.66 / 0.44 / 0.56 (Промені / Глибина / Аврора), `--glass-inner` (картки на полотні) прозоріше, щоб світло було видно й крізь них (під текстом у картці скла завжди більше, ніж у полотна); телефон — вуаль `--atm-veil` 60 % / 35 % / 60 % і скло карток 0.32, бо текст лежить на вуалі без blur.
- Атмосфера статична (дрейф плям прибрано разом з іншими декоративними анімаціями). Передзавантажується лише код розділів (`requestIdleCallback` і hover/focus на пункті навігації), дані — тільки при відкритті розділу; привиди з'являються через 300 мс (CSS-затримка `.ghost`).
- Стан задач Viber safe-mode не опитується за таймером (live-канал їх не віддає): перечитується на focus/visibility/online і кнопкою.
- Скролбар: Chromium/Safari — `::-webkit-scrollbar` (тонкий округлий повзунок на прозорому треку, виразніший при hover і під час скролу через `data-scrolling` з `useScrollActivity`); Firefox — стандартні `scrollbar-width/color`. У Chromium 121+ задані `scrollbar-*` вимикають webkit-стилі, тому в `@supports selector(::-webkit-scrollbar)` вони скидаються на `auto`.
- D1-читання (3.2.19): рядок списку чатів читає підсумок `chat_event_summary` (кількість відкладень, мітка виходу, останні події стану й публікації для токена стану; міграція 0049, тригери на `activity_events`), прогрес автопосту — лічильники `autopost_day_counts` (0050), закриття задач минулих днів іде за частковим індексом (0048). Важка аналітика (рейтинг чатів, спільний для екрана й «Що важливо зараз», когорти, предмети, місячні підсумки цілей, «Події лідів» календаря звітів) кешується за версією подій періоду (`lib/analytics-cache.ts`: сума `activity_day_revisions` періоду, продовженого до сьогодні), а не за глобальною ревізією, яку б'є кожна дія в застосунку. Відповідь `/api/chats` несе `revision`: подія live-каналу з уже баченою ревізією список не перечитує. Міграції з тригерами пишемо лише формами, що вже проходили серверний імпорт D1: звичайний `CREATE TRIGGER` без `CASE … END;` (замість нього `IIF`; на `CASE … END;` у тригері падала стара 0043). Збірки 3.2.18–3.2.19 не розгорталися не через міграції, а через прив'язку R2 (у акаунті R2 не ввімкнено); міграції 0046–0050 застосовано, відбиток staging збігається з репозиторієм.
- Локальне прев'ю: `vinext dev` не стартує (клас Durable Object не експортується в dev). Для візуальної перевірки — `npm run build`, потім `npx wrangler dev --local --port 3000` на локальній D1 із синтетичним власником `owner@example.test`.

## Карта екранів
Функція прототипу 2 → місце в 3.0. Нічого не губиться; рідкісне й технічне живе в «Налаштування → Сервіс».
Позначки: [шелл] каркас · [inspector] праворуч на ПК / Sheet знизу на телефоні · [підтвердження] модальний ConfirmDialog.

**Каркас**
- Навігація (Сьогодні, Платформи, Ліди, Аналітика, Звіти, Бібліотека, Налаштування) → Rail на ПК, Dock + «Ще» на телефоні. Лічильник лідів → тільки в підписі розгорнутої Rail.
- Заголовок розділу, дата → Topbar. Привітання за часом доби → «Сьогодні».
- Глобальні таймери (платформа, 5/10/15 хв, звук, закриття) → Topbar: кнопка-pill з найближчим таймером → скляне меню (Sheet на телефоні).
- Обліковий запис, вихід → меню аватара в Topbar + «Налаштування → Профіль».
- Що змінилося (`AppReleaseDialog`), версія → «Налаштування → Сервіс → Версія» + палітра команд.
- Тест екрана оновлення, автооновлення PWA (банер, екран прогресу, відновлення розділу й скролу) → екран оновлення перестилізовано (`pwa-registration`); тест — «Налаштування → Сервіс».
- Збереження активного розділу (`view-persistence`) → стан розділу в `components/shell` (localStorage), без DOM-хаків.
- Вхід через Google, екран завантаження, ліміт D1 → один екран входу в стилі «Frosted Field».
- Нове: палітра команд (⌘K), PulseRail (телефон).

**Сьогодні** (`components/views/today`; ПК від 1024 px — «Зараз у центрі», телефон і планшет — картки одна під одною з однією прокруткою сторінки; вибір за `useMediaQuery(DESKTOP)` у `today-view.tsx`)
- Одна модель дня (`day-model.ts`, чиста функція `buildDayModel`) складає з наявних джерел єдиний список подій: слоти розкладу Telegram (стор `telegram-schedule-store`, без нового запиту), нагадування з черги лідів зі знімка «Сьогодні», проміжні звіти 13/16/19 (`GET /api/reports/checkpoints`, один запит при відкритті, далі лише за ревізією; «Здати» — наявний `POST`), початок, поточна пауза й кінець дня з `workdays`. Стани подій: виконано, пропущено (слот), час настав, прострочено, попереду; «потребує уваги» — прострочене нагадування, слот, що настав, звіт, який пора здати. Хук `useDay` збирає це з цілями, статусами й діями; лінія «зараз» і відносний час («через 15 хв») оновлюються щохвилини на клієнті (`useMinuteClock`, тік на початку хвилини), таймер активного часу — щосекунди лише поки день триває (`ActiveTime`). Годинник читається в одному місці — `clock.ts`.
- Межі шкали 08:00–21:00 розширюються на цілу годину, якщо події чи «зараз» виходять за них. Нагадування за минулі дні (дата раніше за сьогодні) стоять окремою групою «Прострочено за минулі дні» над шкалою, на завтра — групою «Завтра» під нею.
- Історії пауз у `workdays` немає: відомі `started_at`, `paused_at`, `ended_at`, `active_seconds`. Тому на шкалі видно відпрацьований час від старту, поточну паузу штрихуванням і кінець дня; сумарний час раніших пауз виводиться як різниця (старт → зараз мінус активний час) текстом «пауз раніше N хв» у стані дня й примітці шкали, а їхнє місце не показується. Повна історія пауз потребує мінімальної зміни бекенду (журнал пауз), яку може вирішити лише власник.
- **ПК, «Зараз у центрі»** (`centered-timeline.tsx`, права колонка в `today-view.tsx`): ліворуч заголовок-відлік («Через 15 хв — слот «…»») з дією («Опубліковано», «Готово», «Уточнити») і «Відкрити», чіп «Потребує уваги · N» (тап гортає до першої справи); під ним вікно шкали дня (`.fade-y`: верх приглушується) з лінією «зараз», закріпленою посередині (відступи зверху й знизу в `cqh`, тож будь-яка хвилина стає під лінію без вимірювань). Лінія видна лише в жолобі осі годин (мітки годин, смуга роботи й паузи) і тонким хвостиком після карток, тож картки не розрізає; мітка-пігулка стоїть у жолобі, а не на рядках. Закріплено на «зараз» — мітка «12:50 · зараз», на осі маленький червоний маркер справжнього часу; коли відгорнули — «14:24» і дрібніше «+13 год 21 хв» («−2 год»), а кнопка «До зараз» зі стрілкою вгору чи вниз стоїть біля краю вікна з того боку, де «зараз». Картка під лінією ледь підсвічується (`--raised`, `data-under`); мітка, кнопка й підсвітка оновлюються прямо в DOM на прокрутці, без перемальовування React. Рядки розкладено за часом без накладань (`layoutY`), а час на осі рахується через їхні справжні позиції: `time-axis.ts` — кусково-лінійне відображення «хвилина ↔ піксель» через центри карток (між подіями лінійна інтерполяція, до першої й після останньої вісь продовжується з `PPM`), через нього йдуть мітки годин і засічки, смуга роботи й паузи, маркер «зараз», текст мітки лінії й ціль «До зараз»; де слоти стоять щільно, вісь розтягується, а рядки не рухаються. Щільне минуле може виштовхнути картки вище початку, тоді весь вміст зсувається вниз на однакову величину. Ліворуч вісь годин (смуга роботи — заливка, пауза — штрихування, SVG `<pattern>` `#today-hatch`). Праворуч колонка: привітання з таймером і кнопками, «Цілі дня» (кільця 2×2), статуси списком.
- **Телефон і планшет, «День за годинами»** (`hour-timeline.tsx`): картки одна під одною, як в обраному дизайні: привітання (дата, «Добрий день, <ім'я>», великий таймер, стан, «Пауза»/«Завершити», «⋯»), «Цілі дня» (кільця 2×2 з підписами й «факт / ціль», кнопка розбивки), статуси списком із повним текстом, «День за годинами» (легенда, рядок «Звіт за вчора не здано · До звіту», шкала по годинах зі смугою роботи/паузи ліворуч, подіями й лінією «зараз», нижче «Завтра»). Одна прокрутка сторінки, без вкладених вікон; нічого не стискається заради першого екрана (рішення власника: просторі картки важливіші, ніж «усе на першому екрані»; не «покращувати» без погодження).
- Картка дня (`day-card.tsx`): одна головна кнопка за станом дня («Почати день» → «Пауза» → «Продовжити»), тихе «Завершити» (з підтвердженням незавершених справ), «⋯»: «План дня: цілі й напрямки» (`GoalsPanel` в Inspector), «Повернути день», «Скинути день» (підтвердження). Стан і дії дня — `use-workday.ts` (знімок «Сьогодні» — єдине джерело; перечитується лише на focus/online/повідомлення іншої вкладки).
- Нагадування (`use-reminder-actions.ts`): єдине джерело правди — стор на рівні модуля (множина прихованих `taskKey`, `useSyncExternalStore`), яким користуються шкала, заголовок-відлік «Сьогодні» і вкладка «Нагадування» ліда (`leads/reminders.tsx`). «Готово» / «Надіслано» (нагадування уроку → `reminder_mark sent`, повторний контакт → прибрати дату контакту) ховає рядок одразу в усіх трьох місцях, Toast (і кнопка «Скасувати» у вкладці ліда) дає 8 с на скасування, запит іде після цього часу або одразу при згортанні вкладки; клік по рядку відкриває ліда; нагадування без даних уроку мають «Уточнити». Власні нагадування ліда (kind `custom` у `leadTasks`, ключ `customReminderKey`) проходять тим самим стором і тим самим «Готово / Скасувати»: `doneCustom` → `POST /api/leads/reminders` `op: done` через 8 с; у знімок «Сьогодні» потрапляють невиконані до кінця завтрашнього дня (прострочені, сьогодні, група «Завтра»). «Копіювати» й «Відкласти на завтра» в рядках немає.
- «Цілі дня»: клік по кільцю веде в потрібну чергу чи розділ («Публікації» → «Для публікації», «Нові чати» → черга приєднання, «Відгуки» й «Записи» → «Ліди»); іконка в кутку картки відкриває розбивку за платформами в Inspector (`kpi-panel.tsx`, вкладки-показники). Тон кільця: виконано — ok, у темпі — біле, відстає — warn, сильно відстає — hot, до старту дня — нейтральне.
- Статуси (`status-card.tsx`): звіт за вчора («здано» / «не здано» червоним і підкресленим / «не потрібен», клік → звіт за вчора), звіт сьогодні («не почато» / «чернетка» / «здано»), розклад («наступний слот 11:20 · чат» / «на сьогодні не створено» / «пропущено N» / «усі слоти виконано»). Дані звітів — `useReportStatuses`.
- Слоти: `Опубліковано` (кругла галочка) стоїть у найближчого слоту, слота, що настав, і пропущеного; відмітка йде через наявну дію чату «опубліковано», розклад перечитується.
- Маркери подій (`Marker` у `event-parts.tsx`, спільні для ПК і телефона): кружок 28 px з іконкою lucide 16 px (stroke 1.5): слот — `Send`, нагадування — `BellRing`, проміжний звіт — `ClipboardCheck`, початок дня — `Play`, пауза — `Pause`, кінець дня — `Flag`. Жовтого в шкалі немає: стан передають заливка й обведення. Попереду — тонке обведення `--line`; час настав — інвертований кружок (`--action`); виконано — `Check` на `--raised` без обведення; пропущений слот — пунктирне обведення й іконка `--ink-3` (підпис «пропущено» лишається); прострочене нагадування й звіт, який пора здати й не здано, — обведення й іконка `--signal-hot`, єдиний колір шкали. Початок, пауза й кінець дня мають власну іконку з тонким обведенням. Легенда на телефоні: слот, нагадування, звіт, прострочено, робота, пауза; рядок «Звіт за вчора не здано» — маркер звіту в стані «прострочено».

**Ліди** (`components/views/leads`, дані з `lib/leads`)
- Топбар: перемикач «Дошка | Список», кнопка порядку за давністю відгуку («Новіші спершу» за замовчуванням / «Старіші спершу», зберігається в `localStorage` пристрою; працює в кожній колонці дошки й у списку, а клік на заголовку «Відгук» у списку — те саме, що кнопка; сортування за іншою колонкою вимикає її, доки не натиснуть знову; ліди без дати завжди в кінці) і пошук; «Новий лід» — в меню «Створити» та в кінці колонки «Відгук». Дошка — колонки за етапами воронки (`FUNNEL_STAGES`), шість колонок вміщуються в ширину (від 11,75 рем кожна; якщо екран вужчий, край із продовженням тане — підказка прокрутки, клас `edge-fade-*`), перетягування миші/стилуса змінює етап (оптимістично, з відкатом); на телефоні дошка — стрічка зі scroll-snap, етап змінюється в картці. Список — таблиця з сортуванням.
- Відгуки й записи за день → смуга над дошкою: порожній день — один тихий рядок «Сьогодні ще немає відгуків і записів», є події — компактні картки з чіпами лідів. Фільтри (Активні, Усі відгуки, У куратора, Потрібно уточнити, Прострочені, Архів) — чіпи.
- Inspector ліда (`?lead=…`): шапка (контакти, воронка, наступна дія, факти, перша відповідь, редагування, скасування відгуку, архів) + вкладки Розмова · Нагадування · Заняття · Учні · Історія · Скрипти. У «Заняттях» урок можна провести, перенести, позначити «Учень пішов» або «Учень відмовився» (причина обов’язкова): скасований урок гасить свій запис `lesson_booked` (`cancelled_at`), тож він не рахується в «Записах» цілей, звітів, аналітики й PulseRail, а в історії ліда видно і запис, і скасування. Форми редагування — кроки всередині панелі, підтвердження — модальні.
- **Скрипти ліда** (вкладка «Скрипти», `tab-scripts.tsx`): угорі перемикачі «Учню / Дорослому» (міняє, що підставляється в `[звертання]`) і мова UA/RU, урок для полів (найближчий запланований або вибраний), «Інтерес ліда» (гілка, `leads.interest`; нове значення можна створити з поля). «Рекомендовано зараз» (до 5) за етапом ліда, предметом/напрямком, гілкою й платформою (`lib/leads/domain/script-match.ts`: невідповідні етап чи гілка опускають скрипт, платформа, що не збігається, виключає; шаблони нагадувань вибираються за часом до уроку: до 2 год «за годину», до 36 год «за день»), нижче «Решта скриптів». Текст уже заповнений даними ліда й уроку; порожні поля — рядки вводу з пунктирною рамкою, їх можна дописати перед копіюванням (значення спільні для всіх скриптів вкладки). Копіювання ставить відмітку «Використано» (подія `script_used` в історії ліда, `POST /api/leads/scripts`, не входить у статистику днів і лічильник «Події лідів»); «Зробити свою версію» для офіційного скрипту.
- **Чат-джерело ліда:** у формі ліда поле з пошуком (`ui/combobox.tsx`, примітив Combobox; вікно зі склом, до 50 збігів) замість вставки посилання. Список — усі чати Work OS (`GET /api/leads/chat-options`: один запит на сесію з кешем за ревізією й клієнтським кешем на 10 хв, пошук у браузері за назвою й посиланням, спершу чати вибраної платформи, потім приєднані). Зв'язок зберігається за `leads.source_chat_id`, а не за посиланням (в одного чату бувають різні посилання; власний текст посилання лишається, якщо чат той самий); вибір чату підставляє платформу. «Посилання вручну» — лише коли чату немає в Work OS: id тоді визначається за канонічним посиланням (`normalizeGroupLink`). Аналітика бере чат із `COALESCE(e.chat_id, l.source_chat_id)`, тож пов'язаний лід одразу потрапляє в рейтинг чату. Стан вибору форма передає прихованими полями: `SaveForm` тримає функцію збереження з першого рендеру.
- **Контакт невідомий:** `leads.contact_unknown` (міграція 0046, частковий індекс; існуючі ліди без номера й ніка позначено при міграції). Порожні телефон і Telegram дозволені лише з позначкою (створення, або коли контакт прибирають); з номером чи ніком позначка знімається. Чіп «Без контакту» в «Лідах» (вид `no-contact`). Нагадування «уточнити контакт» у «Сьогодні» не створюються.
- **Власні нагадування:** вкладка «Нагадування» ліда має секцію «Свої нагадування» (`custom-reminders.tsx`): «+ Нагадування» — текст і час (через 2 год, завтра о 10:00, свій час за Києвом), «Готово» (спільний стан із «Сьогодні», 8 с на «Скасувати»), «Змінити», «Видалити» (підтвердження), «Виконані» згорнуто з «Повернути». Зберігаються в `leads.custom_reminders_json` (масив `{id,text,at,doneAt}`; окрема таблиця вимагала б змін резервних копій) і `leads.next_custom_reminder_at` з частковим індексом для «Сьогодні»; запис лише через `POST /api/leads/reminders` із перевіркою «не змінили на іншому пристрої» (команди ліда ці колонки не чіпають).
- «Ліди | Учні» як окремий список учнів неможливий без нового ендпоінта: учні лишаються вкладкою «Учні» в Inspector ліда.

**Платформи** (`components/views/platforms`)
- Ліворуч: платформа (Topbar), дії «Додати чати» / «Дублікати» і, лише на вкладці WhatsApp, «Знайти чати» (автопошук WhatsApp-груп за запрошеннями в публічних Telegram-групах; команда «Знайти WhatsApp-чати» з меню «Створити» перемикає на WhatsApp), черги з лічильниками (для Telegram — один пункт «Відібрані» з лічильником вибраного списку; коли його вибрано, нижче стовпчиком списки-профілі `selected-list-picker.tsx`: «Відібрані 1 · N», вибраний підсвічений, «+ Новий список» унизу; олівець «Редагувати назву» при наведенні, на телефоні завжди, перейменування прямо в рядку: Enter/галочка підтверджує, Esc/X скасовує, порожню назву не зберігаємо; «⋯ → Видалити список» з підтвердженням, останній список видалити не можна; на телефоні списки — горизонтальна стрічка зі scroll-snap), пошук, фільтр профілів і список чатів; праворуч — зона платформи з вкладками: Огляд (ціль публікацій, доступні/приєднані/опубліковані з копіюванням — «Доступні для публікації» не входять у відповідь списку: вантажаться окремим запитом `section=available`, коли відкрито «Для публікації», і ще раз перед копіюванням, Telegram-акаунти й перерва, перевірка заявок WhatsApp), Розклад (Telegram), Автопост (WhatsApp і Viber), Швидкий режим (Viber). На телефоні — сегмент «Чати | Огляд | …».
- Рядок чату: головна дія черги + меню (профіль, +3 дні, повернути, «Я вийшов», видалити назавжди, копіювати, відкрити, історія, архів, перепризначити акаунт). Скасування протягом 8 с — у Toast. Причина архівації, перепризначення, повернення до приєднання, видалення назавжди — підтвердження.
- Telegram «Для приєднання» — два блоки (`join-sections.tsx`). «Черга приєднання»: чати вибраного акаунта (`to_join` з `telegram_account_id` і `join_candidate_at`, порядок відбору), дії «Приєднано» / «В очікування» / «В архів»; лише «Приєднано» з черги рахується в серії приєднань і автоперерві; копіювання «Посилання» / «Назви + посилання» блоками по 5. «Нові чати»: `to_join` без акаунта, партіями по 5 («Партія N · № a–b»), головна дія «У чергу» (закріплює чат за акаунтом, вибраним у цю мить), «Показати ще (N)». З черги чат не зникає в нікуди: «Прибрати з черги» повертає його в нові, «Повернути в чергу приєднання» (меню чату «Для публікації», з підтвердженням, якщо чат у слоті розкладу — слот звільняється) і відновлення з архіву кладуть чат у чергу. «Топ-N до приєднання» з «Відібрані» додає одразу в чергу вибраного акаунта. Лічильник «Для приєднання» = черга вибраного акаунта + нові чати (з `chat_queue_counts`, без нових лічильників).
- «Відібрані» праворуч (`selected-chats.tsx`, `selected-rows.tsx`, `selected-in-work.tsx`) — робота партіями: липка шапка (назва, «N чатів · нових M · файл від …», «Замінити файл») і «Наступні N з M» з розміром партії 10/25/50 (зберігається) та головною дією «+ Усі N у чергу» (в чергу вибраного акаунта; без «Скасувати», бо наявне API не вміє безпечно прибирати створені чати). Рядки компактні: номер у файлі, назва, посилання, повідомлення й дата (mono), «+ У чергу» і «×» «Пропустити»; після дії рядки гаснуть, решта зсувається Flip, партія добирається. Під партією один згорнутий рядок «Уже в Work OS · N» із розбивкою за статусами; розгортання — компактний список зі статусом і акаунтом (сторінки по 50) і група «Пропущені · N» з «Повернути»; стан згортання зберігається. Пропущені посилання зберігаються в метаданих списку в `user_settings` (`dismissed`, дії `skip`/`unskip`, один запис на дію, без нових читань). Пошук із текстом іде по всьому списку (до 50 + «Показати ще»), порожнє поле повертає партію. Нових не лишилось — «Усі чати цього списку вже в Work OS або пропущені.»; порожній список — одна дія «Завантажити файл» і короткий опис формату. Файл завжди імпортується у вибраний список. Лічильники черг ліворуч видно й у «Відібраних»: для цього один разовий запит `/api/chats?status=to_join&limit=1` (лише коли лічильників акаунта ще немає або прийшла live-подія).
- Автопост (WhatsApp, Viber) — одна черга задач (`lib/messenger-automation.ts`, політика збоїв у `lib/messenger-automation-outcome.ts`). Партія береться за тим самим відбором, що й «Для публікації» (готовий, не відкладений, без публікації сьогодні, дозволений профілем), чат — не більше одного разу на день; чати без публікацій і з найдавнішою публікацією йдуть першими. Збій обробляється за кодом: «пишуть лише адміни», «вилучено / забанено», «посилання недійсне» → архів із причиною («Пишуть лише адміни», «Забанено», «Чат не існує»); заявка на вступ без відповіді (WhatsApp) → «Очікування»; повільний режим чи ліміт → відкласти на завтра; тимчасове (до відправки) → ще 2 спроби, далі пропуск на сьогодні; незрозуміле й будь-який збій після натискання «Надіслати» → «Потребують рішення» (`autopost-attention.tsx`: «Спробувати ще», «Відкласти», «В архів»), такий чат не потрапляє в нові партії. Проблеми середовища (runner чи Viber не готові) не рахуються спробами: черга стає на паузу.
- Автопост Viber (`viber-autopost-card.tsx`, адаптер `scripts/viber-android.mjs`): Android у Waydroid, керування Viber через `adb` (uiautomator, input, `am start`). Runner ні Waydroid, ні Viber не запускає й не перезапускає, лише перевіряє (дія `status` раз на хвилину, повідомлення live-каналу `progress / viber_status`, без D1): `waydroid status` (сесія й контейнер RUNNING), `adb` авторизований, Viber і клавіатура ADBKeyBoard встановлені, мова Android англійська; інакше задача лишається в черзі (пауза, не спроба), а картка пояснює причину (`waydroid_not_running`, `waydroid_frozen`, `android_unreachable`, `android_unauthorized`, `viber_not_installed`, `adbkeyboard_missing`, `viber_not_activated`, `viber_language`). Умови середовища (одноразові, root): Viber із Google Play активований як додатковий пристрій (QR зі смартфона), `ADBKeyboard.apk` (`github.com/senzhk/ADBKeyBoard`, лише дозвіл BIND_INPUT_METHOD, без мережі), `waydroid prop set persist.waydroid.suspend false`, `ufw` пропускає `waydroid0` (DNS і форвардинг). Розсилка лише за кнопкою «Автопост черги» (вибір партії 1 / 5 / 20 / усі), з прогресом і «Зупинити». «Зупинити» скасовує задачі в D1, а Durable Object (`/autopost-wake`) повідомляє runner (`cancel / autopost`): адаптери Viber і WhatsApp перевіряють це перед кожним кроком і востаннє безпосередньо перед кнопкою відправки, після неї скасувати вже не можна. Швидкість: стан екрана й координати беруться з `dumpsys activity top` (≈60 мс, без текстів: id, видимість, фокус, координати від `mBounds` вікна), а повний `uiautomator dump` (≈2,2 с) лише там, де потрібен текст (заголовок чату, підпис, останнє повідомлення, діалоги); цикл на чат ≈14 с, `timings` у відповіді й журналі runner. Одне завдання: Viber стартує з чистого стану (`am start -f 0x10008000`), чат відкривається за інвайтом `invite.viber.com`, заголовок має збігатися з назвою (хвіст «в/у Viber» у назві Work OS ігнорується; інакше `target_unconfirmed`) і має бути поле повідомлення. Якщо чат ще не приєднаний (сторінка запрошення з кнопкою «Join Community / Join»), автопост сам вступає, але лише коли назва на сторінці вступу збігається з назвою в черзі (інакше `target_unconfirmed` без вступу); результат читається за екраном: розмова з полем — публікуємо далі, діалог «Unable to join… blocked» → `viber_banned` (архів «Забанено»), розмова без поля → `viber_read_only` (архів «Пишуть лише адміни»), неактивне посилання → `viber_chat_missing` (архів «Чат не існує»), кнопка, що двічі не подіяла → `viber_not_joined` («Потребують рішення»; «Очікування» у Viber немає). Тексти описів спільнот і списку чатів як відмова не читаються, відмову визначає лише екран без кнопки вступу й без списку чатів; фото кладеться в `Pictures` Android під новою назвою `workos-autopost-…` (найновіше в галереї; видаляється через 3 хв без відправок), далі в чаті «+» → «Gallery» (екран «All Media», `FullscreenGalleryActivity`) → найновіше фото → попередній перегляд, підпис вводиться клавіатурою ADB (вмикається на початку відправки, потім дотик у поле, поки дерево не покаже фокус, потім `ADB_INPUT_B64`, повний збіг тексту перевіряється, стара клавіатура повертається лише після відправки, бо екранна закрила б «Send»), «Send» (повторний дотик лише якщо вікно перегляду не закрилось за 8 с) і підтвердження: розмова з тією самою назвою, останнє повідомлення починається з підпису, час збігається з хвилиною годинника Android, значок статусу не червоний. Інлайн-панель галереї під полем повідомлення не використовується: вона часто валить Viber, а `uiautomator dump` на ній валить гарантовано. Будь-яка неоднозначність закінчується без відправки; після «Send» нічого не повторюється. Фото й текст спільні для WhatsApp і Viber (вкладка «Автопост» у WhatsApp: збережений текст, а без нього підпис із Бібліотеки; міст буфера Waydroid передає лише текст і лише з вікном у фокусі, тому вставка не підходить). Відкриття за інвайтом на реальному посиланні перевірено на `viber_not_joined` і на невідповідності назви; повна публікація перевірена в «Мої нотатки» й, після цього виправлення, ще не на реальному чаті.

Дошка за статусами (перетягування між колонками й у колонці через `use-drag-sort`; позиція `REAL`, дія `move`) і список; архів; пошук у Topbar. Фото: кліком, перетягуванням і вставкою з буфера (Ctrl+V), стискаються в браузері до ≈700 КБ JPEG (`image-compress.ts`), файли в R2 (`FILES` → `work-os-staging-files`, ключі `dev/<власник>/<uuid>`, у D1 лише ключі; `POST/GET/DELETE /api/dev-items/files`, перевірка типу, магічних байтів і власника; прибрані з запису й незбережені фото видаляються); прив'язка `FILES` → бакет `work-os-staging-files` (R2 увімкнено власником, Standard, без публічного доступу) стоїть у `wrangler.jsonc` лише для staging з 3.2.22 і не прибирається: без R2 в акаунті збірки не розгортаються (так було з 3.2.18 до 3.2.20); у production прив'язки немає, там завантаження відповідає, що сховище не підключено. «Скопіювати як задачу» кладе короткий текст (тип, назва, пріоритет, опис, чекпоінти `- [x]`, нотатки, кількість фото) для чату з Claude. Таблиця `dev_items` входить у резервну копію (схема 14); самі файли з R2 у копію не потрапляють.
