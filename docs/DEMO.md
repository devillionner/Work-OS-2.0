# Публічна демо-версія Work OS

Окремий воркер `work-os-demo` з вигаданими даними: будь-хто заходить за посиланням без входу й може потикати всі розділи. Реальних даних у ньому немає взагалі.

## Що це і чого в ньому немає
- Своя база D1 `work-os-demo-db`, той самий код застосунку, змінна `DEMO_MODE=1`. Без R2, без Google-входу, без runner і без жодних секретів.
- Автопост, runner, executor, автопошук чатів, резервні копії, імпорт, вихід, фото й вкладення не виконуються: кнопки видно, а замість дії показується Toast «У демо-версії недоступно». Зовнішніх викликів воркер не робить (будь-який `fetch` на чужий хост отримує 403).
- Під Topbar тонка смужка «Демо-версія · дані вигадані · скидаються щоночі».
- Staging і production не змінюються: демо-код потрапляє в збірку лише з `CLOUDFLARE_ENV=demo`.

## Захисти
- Воркер відмовляється працювати (503), якщо в `users` є хтось, окрім `demo@example.test`, тож підключена за помилкою справжня база не постраждає. Нічне скидання теж не стирає таку базу.
- На IP: 150 читань і 30 записів за хвилину. На весь воркер за добу (UTC): 6000 читань і 600 записів; після стелі записи (або все) вимкнені до нічного скидання, екран пояснює це Toast.
- Нічне скидання за cron `0 0 * * *` (00:00 UTC, 02:00–03:00 за Києвом): стирає всі таблиці й засіває заново одним `batch`.

## Вартість у D1 (спільний ліміт акаунта зі staging)
- Нічне скидання: ≈27 тис. записаних і ≈40 тис. прочитаних рядків (локальний лічильник; закладати до 40 тис. записаних).
- Візит у всі сім розділів: ≈4,3 тис. прочитаних рядків, ≈110 звернень до D1. Один запис (відмітка публікації тощо): ≈25–30 записаних рядків.
- Верхня межа від стелі записів: 600 × 30 ≈ 18 тис. рядків на добу. Разом із скиданням до ≈60 тис. із 100 тис. добового ліміту записів Free-плану.

## Розгортання (кроки власника, один раз)
1. Cloudflare → Workers & Pages → Create application → Import a repository (Connect to Git) → репозиторій `devillionner/Work-OS-2.0`.
2. Поля: Project name (Worker name) `work-os-demo`; Production branch `main`; Root directory `/`; Build command `npm run build:demo`; Deploy command `npm run deploy:demo`. Змінні збірки не потрібні.
3. Save and Deploy. Перша збірка сама створить базу `work-os-demo-db` (якщо токен збірки не має права D1 Edit, збірка зупиниться з поясненням: тоді Storage & Databases → D1 SQL database → Create database з назвою `work-os-demo-db` і повторіть збірку), застосує міграції лише до неї, засіє вигадані дані й розгорне воркер. Cron береться з конфігу.
4. Посилання: `https://work-os-demo.devillionner.workers.dev` (поддомен той самий, що в staging).

Після цього кожен push у `main` оновлює і staging, і демо.

## Локальна перевірка
`CLOUDFLARE_ENV=demo npm run build`, база з усіма міграціями у файлі локальної D1 `work-os-demo-db`, далі `npx wrangler dev --local --config dist/server/wrangler.json --test-scheduled`; нічне скидання викликається `curl "localhost:8787/cdn-cgi/handler/scheduled?cron=0+0+*+*+*"`.
