# Runner Work OS: на чому він тримається і як поставити його на новий Linux

Runner — це програма на вашому ПК, яка виконує автопост: відкриває WhatsApp Web і Telegram Web у браузері та керує Viber в Android (Waydroid). Work OS у хмарі лише дає йому задачі через live-канал.

## Як переїхати на нову систему (кілька хвилин)

**1. На старій системі** (runner працює): «Налаштування → Сервіс → Runner на цьому ПК» → **«Зберегти для перенесення»**. На ПК з'явиться вікно: введи пароль архіву (двічі) і, якщо в даних Android є файли їхніх системних власників, пароль користувача для `sudo`. Далі runner сам закриє свій браузер і зупинить Android (Waydroid), запакує дані, зашифрує **на ПК**, вивантажить у хмару й усе підніме назад. Прогрес видно в картці; готово, коли там написано «Збережено 10.11 о 14:20 · 1,4 ГБ». Якщо runner працює у твоєму щоденному браузері, він спершу питає, чи можна його закрити. Пароль у Work OS не потрапляє й не відновлюється: без нього архів не відкрити.

**2. На новій системі**: у тій самій картці «Встановити на новій системі» → «Створити код» → скопіюй команду й виконай її в терміналі:

```bash
curl -fsSL https://<сайт>/runner/install | bash -s -- --site https://<сайт> --code 7KQ4-M2XP
```

Код одноразовий і діє 15 хвилин. Інсталятор перевірить SHA-256 пакета, поставить усе потрібне (пакети, Node, браузер, Waydroid, трей і сервіс), обміняє код на токен (входити в Work OS у браузері runner не треба) і, побачивши архів у хмарі, спитає «Відновити входи з архіву від 10.11 (1,4 ГБ)?» → пароль. Після цього runner онлайн, WhatsApp, Telegram і Viber без QR. Без архіву (перший ПК) інсталятор просто прив'язує runner і нагадує, де увійти в месенджери.

Наявне на новій системі не затирається, а переїжджає в `*.bak-ДАТА`. У хмарі лишаються два останні архіви, старші видаляються самі; архів можна видалити кнопкою «Видалити архів із хмари».

### Що ставиться на ПК

Лише runner: скрипти, трей і адаптери WhatsApp/Telegram/Viber в `~/.local/share/work-os/runner` (пакет із сайту того самого збирання, що й сайт; репозиторію, git і коду сайту на ПК немає) і програми, без яких він не працює: Node, браузер, Waydroid із Viber. Сервіс `work-os-runner-tray.service` і обробники посилань ставляться на рівні користувача. Runner, встановлений із сайту, **сам оновлюється**, коли версія сайту інша, а він простоює (завантажує пакет із перевіркою суми, трей перезапускає його, коли він не працює). Runner із робочої копії репозиторію цього не робить: його оновлює трей за зміною файлів.

### Команди інсталятора

Усі параметри передаються після `--`, наприклад `curl -fsSL https://<сайт>/runner/install | bash -s -- --site https://<сайт> --check`.

| Параметр | Що робить |
|---|---|
| `--code КОД` | прив'язка за одноразовим кодом і пропозиція відновити входи |
| `--restore` | запропонувати відновлення з архіву в хмарі (з уже прив'язаним runner) |
| `--check` | перевірка готовності без змін (теж: `~/.local/share/work-os/runner/scripts/install-runner.sh --check`) |
| `--dry-run` | показати, що було б зроблено; пакет розпаковується в тимчасову теку |
| `--remove` | прибрати runner, сервіс і обробники посилань; входи, налаштування й дані Waydroid лишаються |
| `--remove --purge` | ще й профіль браузера runner, налаштування й стан (дані Waydroid: `~/.local/share/waydroid`, вручну) |
| `--browser`, `--arm`, `--android-windows`, `--skip-waydroid`, `--yes` | як раніше: вибір браузера, перекладача ARM, правила вікон Android, пропуск Viber, відповіді за замовчуванням |

Підтримано: Arch/CachyOS/Manjaro/EndeavourOS (`pacman`), Fedora (`dnf`), Ubuntu/Debian/Mint (`apt`), x86_64. **Не підтримуються й відхиляються одразу, до будь-яких змін:** NixOS, незмінні Fedora Silverblue/Kinoite/Sericea/Onyx/CoreOS і Bazzite/Bluefin/Aurora, SteamOS, Vanilla OS, openSUSE/SUSE, невідомі дистрибутиви; Windows і ARM-комп'ютери.

## Від чого залежить runner

| Що | Навіщо | Специфічне? |
|---|---|---|
| Node.js ≥ 22.13 | Сам runner (`scripts/chat-discovery-runner.mjs`) | Ні. Якщо в системі старіший, інсталятор ставить офіційний Node без root з перевіркою SHA-256 |
| Залежності репозиторію (`npm ci`) | Імпорти спільного коду | Ні |
| Браузер із `--remote-debugging-port=9222` і прапорцями `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling` | Runner керує вкладками WhatsApp Web і Telegram Web через CDP; прапорці потрібні, щоб приховані вкладки не гальмували | Ні. Тут це Opera з `~/.local/share/applications/opera.desktop`; інсталятор уміє Opera, Chrome, Chromium, Brave |
| Профіль браузера з входами в WhatsApp Web і Telegram Web | Без нього треба сканувати QR | Ні. Тут це профіль вашої Opera; інсталятор за потреби створює окремий (`~/.local/share/work-os-runner-browser`) |
| Waydroid (образ GAPPS) | Android, у якому працює Viber | Ні, але пакети й kernel різні: `binder` у ядрі, на Ubuntu/Debian репозиторій `repo.waydro.id` |
| Перекладач ARM (`libhoudini` для Intel, `libndk` для AMD) | Viber — ARM-застосунок, а Waydroid на x86 | Ні. Ставиться через `waydroid_script` (закріплений комміт) |
| `persist.waydroid.suspend=false` | Інакше Android засинає й adb пропадає | Ні |
| `adb` (`android-tools`) і ключ `~/.android/adbkey` | Керування Android; ключ дописується в `adb_keys` Waydroid без root | Ні |
| ADBKeyBoard (`com.android.adbkeyboard`) | Введення підпису у Viber клавіатурою adb | Ні; APK перевіряється за SHA-256 |
| Viber, активований як додатковий пристрій | Сам автопост Viber | Ні; QR зі Viber на телефоні |
| Правила фаєрвола для `waydroid0` (`ufw route allow in/out on waydroid0` або зона `trusted` у firewalld) | Без них Android не має інтернету | Залежить від фаєрвола: тут `ufw` |
| systemd user-сервіс `work-os-runner-tray.service` | Піднімає трей при вході й після збою | Потрібен systemd (є скрізь у підтриманих системах) |
| Трей: Python `gi`, GTK 3, AppIndicator | Іконка, яка стартує й перезапускає runner | Назви пакетів різні, інсталятор знає їх; у GNOME потрібне розширення AppIndicator |
| Обробники `workos-runner://` і `workos-waydroid://` (`.desktop` + `xdg-mime`) | Кнопки «Запустити runner» і «Відкрити вікно» у Work OS | Ні |
| Правило вікон Android | Вікна Waydroid не виринають на робочому столі під час автопосту | **Залежить від робочого столу**, див. нижче |
| Токен runner | Авторизація live-каналу | Ні; береться зі сторінки Work OS у браузері runner |

### Вікна Android залежно від робочого столу

- **Hyprland** (як зараз): `scripts/hyprland-android-windows.mjs` сам ставить правило під час роботи адаптера. Інсталятору нічого додавати не треба.
- **KDE Plasma**: інсталятор додає правило KWin «Work OS: вікна Android» (клас `waydroid.*`: без фокусу, не в панелі завдань, згорнуте). **Не перевірено наживо.**
- **Інші** (GNOME, XFCE, інші Wayland/X11): інсталятор вимикає `persist.waydroid.multi_windows`, Android працює одним вікном, яке саме не з'являється. Розмір цього вікна інший, ніж у режимі за замовчуванням, а жести адаптера Viber від нього залежать. **Не перевірено: після встановлення проженіть автопост Viber на 2–3 чатах.** Змінити вибір: `--android-windows hide|off|keep`.

## Що входить в архів і як він захищений

В архіві: профіль браузера runner (сесії WhatsApp Web і Telegram Web: IndexedDB і Local Storage), дані Waydroid (`~/.local/share/waydroid`: Android з уже активованим Viber), ключ adb й пам'ять Telegram. **Кеші не пакуються** (Cache, Code Cache, GPUCache, CacheStorage і ScriptCache браузера, кеші Waydroid/Android). Налаштування ПК (`runner.env`: токен, шлях браузера) в архів не йдуть, бо нова система отримує власний токен із коду. Профіль щоденного браузера (Opera, Chrome…) на новій системі розгортається як окремий профіль runner.

Шифрування (`scripts/runner-vault.mjs`, без зовнішніх програм): scrypt (N=2^17, r=8) із випадковою сіллю → AES-256-GCM по шматках 4 МіБ; кожен шматок має тег автентичності з номером шматка й ознакою «останній», тож підміна, перестановка й обрізання виявляються. Неправильний пароль чи пошкодження видно до розпакування: після завантаження звіряється SHA-256 файлу, далі іде повний прохід перевірки без запису і лише потім розпакування. Для розпакування й пакування потрібне місце на диску: розмір архіву (тимчасовий файл у `~/.cache/work-os`). Вивантаження й завантаження — частинами по 32 МБ через воркер (multipart R2), кожна частина з повтором після обриву. Метадані (дата, розмір, сума, версія runner) — один рядок `user_settings`.

Дані Android у Waydroid належать системним користувачам Android, тож пакування й розпакування їх потребує root. Перед запитом пароля `sudo` на ПК написано навіщо; пароль передається лише одному процесу `sudo` і ніде не зберігається.

## Що перевірено і що ні

Перевірено (3.16.0, локально, `wrangler dev` із локальним R2): код встановлення діє один раз і гасне через 15 хв, обмеження невдалих спроб; збереження 323 МБ (11 частин) через проксі, що рве з'єднання посеред частини, з імітованим збоєм ще однієї частини; завантаження з обривом і усіченою частиною; перевернутий байт у дорозі (виявляється за SHA-256, нічого не розкладається); неправильний пароль, обрізаний, пошкоджений і переставлений файл (до розпакування); кеші не в архіві, вміст профілю й Waydroid збігається з оригіналом; наявне відкладається в `*.bak-ДАТА`; лишаються два архіви, старіші зникають з R2; пакет runner у чистій теці (22 файли, лише runner), запуск runner із пакета з токеном, самооновлення з іншої версії; `--dry-run` на Arch, Fedora й Ubuntu (`OS_RELEASE_FILE`), відмова на NixOS, openSUSE, Silverblue, Bazzite, невідомому; закриття браузера через CDP; весь ланцюжок «кнопка в картці → DO → runner → прогрес у браузері».

Не перевірено наживо: вікно пароля GTK (лише компіляція), права root через справжній `sudo -A` (перевірено з тестовим `sudo`), закриття щоденного Opera й повернення вкладок, зупинка й запуск справжнього Waydroid, справжнє встановлення в чистому контейнері чи ВМ (на цьому ПК немає docker/podman/distrobox; `apt` і `dnf` гілки лише `--dry-run`), встановлення Waydroid з нуля, відновлення в іншому дистрибутиві (профіль Opera → Chrome), завантаження ADBKeyBoard за закріпленою сумою, правило KWin і режим без `multi_windows`, робота на staging із справжнім R2.
