# Дизайн-система Work OS 2.0

Контракт: CORE-03/05/10–18, UX-02 у [PRODUCT_REQUIREMENTS](PRODUCT_REQUIREMENTS.md).
Фактичні спільні компоненти — `components/ui`; токени — `app/globals.css`.
Правила успадковані з read-only Prototype DESIGN_SYSTEM і адаптовані до React.
Shared `Button` тепер відповідає базовій ієрархії нижче: primary action нейтрально-чорна,
синій лишається акцентом/focus color, а всі shared size variants мають interaction target
не менше 42 px. Повна візуальна QA всіх legacy/app-specific controls ще не завершена.

## Основні правила

- Білі робочі поверхні, чорний головний текст/primary action, один синій акцент.
  Червоний/жовтий — тільки небезпека/попередження. Нейтральні відтінки задають ієрархію.
- Одна основна дія; заголовок/дата → 2–5 потрібних показників → режими → поточний
  список. Керування базою, імпорт, дублікати, історія та архів відкриваються за потреби.
- Сітка 4 px; відступи 8/12/16/24/32 px. Контрол ≥42 px desktop, ≥44 px touch.
  Shared `Button` задає 42 px для compact/default та 44 px для large; mobile-specific
  controls мають підніматися до 44 px там, де viewport/touch contract цього вимагає.
  Орієнтири радіусів 7/10/14 px, основна ширина контенту до 1040 px; довгі таблиці
  можуть мати обґрунтований виняток без розтягування всіх форм.
- Основний текст 14 px+, line-height 1.45–1.55; заголовок 24 px (Today до 30 px).
  Метрика завжди показує період, визначення/формулу/джерельні події за потреби.
- Видимий focus-visible, семантичні labels, дієслівні назви кнопок, aria-label/title
  для іконок. Modal утримує фокус, Escape працює без втрати незбережених змін;
  прокручується вміст, кнопки залишаються доступними над iPhone-клавіатурою.
- Черга має loading/empty/error з retry, partial success та completed. Після дії
  результат оновлюється без ручного refresh; контекст платформи/акаунта зберігається.
- Основний пошук один; не більше двох постійних фільтрів. Видимі назви станів і
  синоніми мають знаходитися пошуком. Скидання фільтрів — одна контекстна дія.

## Спільні шаблони

Платформа: назва й результат сьогодні → приєднання/очікування/публікації →
інструменти режиму → список → історія/архів. Telegram-розклад і вибір чатів
належать конкретному account ID. Непризначені чати спільні тільки до відбору.
Threads не має груп/часових слотів. Підбір оголошення є необов’язковою дією публікації.

Дублікати: окремий інструмент, групи кандидатів між усіма станами й архівом;
точний URL сильніший за збіг назви. Кожен запис можна відкрити/перейменувати/
архівувати з причиною. Назва не дає підстави автоматично видалити інший URL.

Лід: контакт відокремлений від учнів; уроки, follow-up та переписка мають окремі
компактні блоки. Контакт може не навчатися; кожен учень має власний вік/клас.

Звіт: один контроль дати зі стрілками/date picker/«Сьогодні», без майбутніх дат,
видимий історичний контекст та «ще не створено / збережено». Alt+стрілки перемикають
день. Створення ліда переносить дату обліку, але не підміняє дату уроку.

Аналітика предметів: одна компактна таблиця, явні межі періоду та «Усього»;
7/30 днів включають кінцеву дату. На mobile прокручується тільки таблиця.
Нуль відгуків = «—» для конверсії; подієве відношення понад 100% не обрізається.

Темп Telegram: хвилини й публікації/год — одне точне значення `60/rate`;
дробові хвилини не округлюються приховано. Ручний набір не доповнюється автоматично.

## Перевірка

Desktop Windows/Linux, вузький viewport і реальний iPhone Safari: клавіатура,
touch-цілі, focus, довгі назви/URL, порожні й помилкові стани, повернення з месенджера,
відсутність перекриття нижньою навігацією/клавіатурою. Скриншоти й висновки належать
конкретному commit; неперевірена сумісність не отримує статус «готово».
