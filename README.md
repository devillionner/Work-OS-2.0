# Work OS 3.0

Приватний вебзастосунок (PWA) для щоденної роботи з чатами, публікаціями, лідами, звітами, цілями та аналітикою. Один власник, один оператор.

## Поточний стан

- інтерфейс 3.0 на дизайн-системі «Frosted Field»: теми «Ніч» і «День», атмосфери тла, чорна рейка навігації на комп'ютері й нижня панель на телефоні;
- сім розділів: Сьогодні, Платформи, Ліди, Аналітика, Звіти, Бібліотека, Налаштування; деталі сутностей відкриваються в Inspector (комп'ютер) або шторці знизу (телефон);
- власний Cloudflare Worker і окрема база D1; зміни між пристроями йдуть live-каналом (Durable Object);
- Google-вхід для одного дозволеного акаунта;
- резервна копія й контрольоване відновлення відсутніх записів у «Налаштування → Сервіс» і «Небезпечні дії».

Поточна хмарна адреса: <https://work-os-2.devillionner.workers.dev>

## Локальний запуск

Потрібен Node.js 22.13 або новіший.

```bash
npm install
npm run build
npx wrangler dev --local --port 3000
```

`vinext dev` не стартує (клас Durable Object не експортується в dev), тому для перегляду інтерфейсу збираємо й запускаємо Worker локально. Локальний режим використовує окрему локальну копію D1 і не змінює хмарні дані; після кожної збірки сервер треба перезапускати.

## Перевірка перед push

```bash
npm run lint && npm run typecheck && npm run build
```

Push у `main` автоматично оновлює staging (Cloudflare Workers Builds), тому падіння будь-якого кроку означає не пушити. Деталі: [локальна розробка та D1](docs/LOCAL_DEVELOPMENT.md).

## Публікація у власний Cloudflare

Deploy є окремою контрольованою операцією після локального `npm run verify`.
Після одноразового `npx wrangler login`, для staging:

```bash
npm run deploy
```

Для production environment потрібно вибрати **до build**. У PowerShell, лише під час погодженого release:

```powershell
$env:CLOUDFLARE_ENV = 'production'
npm run build
# Перевірити Worker і DB у dist/server/wrangler.json; лише після успіху build:
npx wrangler deploy --config dist/server/wrangler.json
Remove-Item Env:CLOUDFLARE_ENV
```

Без `CLOUDFLARE_ENV` команда `npm run deploy` працює зі staging-конфігурацією. Production deploy
не виконується автоматично від push у `main`, щоб випадково не змінити робочі
дані.

Не залишати `CLOUDFLARE_ENV=production` для звичайної розробки. SQL-міграції не
входять у deploy; зміни production D1 та фінальний перенос із Prototype потребують
прямого підтвердження. Щоденного resync немає. Усі тести/restore-drill локальні.

Сайт працює незалежно від підписки ChatGPT. Робочі дані зберігатимуться в
Cloudflare D1, а код — у цьому GitHub-репозиторії.

## Архітектурні принципи

1. Хмара є основним джерелом даних; браузер не є базою даних.
2. Усі робочі результати зберігаються як події: публікація, відгук, запис, урок, звіт.
3. Екрани платформ мають спільну структуру, а платформні правила є конфігурацією.
4. Міграція зі старої версії відбувається тільки через резервну копію, перевірку та попередній перегляд.
5. Зовнішні корпоративні системи не інтегруються і не змінюються.
